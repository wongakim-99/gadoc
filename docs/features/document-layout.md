# 문서 페이지 구성

## 사용 방법

- 문서 목록의 **문서 허브 만들기**는 문서·자료·업무 3열과 이번 주 섹션이 있는 새 페이지를 만듭니다. 기존 문서를 이동하거나 덮어쓰지 않습니다.
- 편집기 위 **2열 배치**, **3열 배치**, **문서 허브** 또는 `/` 메뉴에서 현재 문단 다음에 배치를 추가합니다. 열 안에서는 제목, 일반 문단, 링크, 이미지, 데이터베이스 등 기존 블록을 사용합니다.
- **문서 링크**에서 접근 가능한 기존 문서를 검색해 선택합니다. 선택기를 열었던 문단 바로 다음에 일반 문서 링크를 추가합니다. 원본 문서나 접근 권한은 복사하지 않습니다.
- 각 열의 **문단** 버튼은 해당 열 안에 문단을 추가합니다. **아래에 쓰기**는 열 바깥, 배치 다음에 문단을 만듭니다.
- **전체 너비**로 넓혀 구성할 수 있습니다. 편집 영역이 좁은 모바일·옆 패널에서는 열 순서를 유지한 채 세로로 쌓입니다.

## 저장과 권한

`documentColumns`와 `documentColumn`은 기존 BlockNote 자식 블록입니다. 별도 편집기·HTML 문자열·로컬 전용 저장소를 만들지 않으며, 브라우저와 서버 공동 편집 코덱이 동일한 document-core 설정을 사용합니다. 내부 문단도 기존 Yjs 공동 편집, 자동 저장, 버전 이력 및 문서 권한 검사를 거칩니다.

문서 링크 선택기는 열 때마다 인증된 문서 목록을 읽고, 다른 워크스페이스·휴지통·현재 페이지·데이터베이스 행 페이지를 제외합니다. 실패하면 목록을 숨기고 재시도하며, 닫았다가 다시 열면 권한을 새로 확인합니다. 링크 삽입 시 원래 문단이 삭제됐다면 임의 위치에 넣지 않습니다. 삽입된 제목은 일반 링크 텍스트이므로 원본 이름 변경에 자동 동기화되지는 않습니다. 링크를 통한 문서 열기는 서버의 현재 권한을 다시 적용합니다.

새 페이지나 사용자가 선택한 삽입 위치에만 적용합니다. 운영의 기존 페이지나 업무 분류를 자동 변경하는 마이그레이션은 없습니다. 배포 시에는 새 블록을 함께 이해하는 서버와 웹을 같이 배포해야 합니다.

## 검증 범위

- 2열 실시간 전달, 서로 다른 열의 오프라인/온라인 편집 병합, 서버 JSON 저장과 새로고침 복원.
- 모바일 세로 배치 및 가로 넘침 방지, 읽기 전용 문서의 삽입·열 편집 도구 숨김.
- 문서 선택기의 권한 필터, 오류 재시도, 선택 이전 삽입 위치 유지, 링크 저장 및 원본 내용 보존.
- 허브를 실제 새 문서로 생성하고 `/` 메뉴로 추가 배치를 삽입.

임의 비율의 열 너비 드래그 조절, 링크 제목의 자동 동기화, 별도 캔버스와 Mermaid는 이 배치 기능과 구분합니다.
