# 리액션 참여자

## 사용

메시지와 스레드 답글의 기존 이모지 버튼은 본인 반응을 추가·취소합니다. 마우스를 올리면 현재 워크스페이스 캐시에 있는 참여자 이름을 요약해서 볼 수 있습니다. 옆의 `리액션 참여자 보기`는 반응을 바꾸지 않고 별도 목록을 엽니다.

목록은 전체 또는 이모지별로 볼 수 있고, 실시간 메시지 갱신에 맞춰 참여자가 추가·제거됩니다. 키보드로 열고 Escape로 닫으면 원래 버튼으로 포커스를 돌려줍니다. 모바일과 스레드에서도 같은 컴포넌트를 사용합니다.

## 권한과 프로필

메시지 목록의 캐시는 새 요청 없이 구독합니다. 참여자 창을 열 때 기존의 권한 검사된 멤버 API를 한 번 조회하며, 종류를 바꿀 때마다 다시 요청하지 않습니다. 조회 실패 시 재시도할 수 있고 새로고침으로 이름 변경·멤버 목록을 다시 확인합니다.

이메일과 내부 사용자 ID는 목록에 표시하지 않습니다. 현재 허용된 멤버 정보에서 이름을 찾지 못하면 공통 안내 이름을 표시합니다. 사진은 인증된 비공개 파일 프록시 경로만 사용하고, 외부 추적 URL은 자동 요청하지 않습니다. 사진이 없거나 로드하지 못하면 이니셜을 표시합니다.

이 변경은 기존 프로필 사진의 **표시**를 지원합니다. 프로필 업로드·크롭·상태 편집·기본 이미지 선택기와 커스텀 스티커 제작 기능을 구현했다는 뜻은 아닙니다.

## 동시성

기존 조회 후 저장 방식에서는 두 사용자가 동시에 새 반응을 추가하면 같은 이모지가 두 항목으로 저장될 수 있었습니다. 이제 한 MongoDB 문서 업데이트 파이프라인으로 참여자 토글을 계산합니다. 서버가 읽은 뒤 저장하는 사이의 덮어쓰기가 없으며 다른 이모지와 본문은 유지합니다.

기존 중복 항목은 화면에서 합쳐서 표시합니다. 해당 반응을 다음에 토글할 때 서버도 모든 기존 참여자를 합쳐 하나의 항목으로 정리합니다. 운영 DB를 일괄 덮어쓰거나 과거 참여자를 삭제하는 마이그레이션은 없습니다. 반응 이름은 비어 있지 않은 최대 100자 문자열이며, 제어 문자를 허용하지 않고 MongoDB 표현식에 넣을 때 리터럴로 취급합니다.

## 검증

`tests/e2e/reaction-participants.e2e.spec.ts`는 두 클라이언트 갱신, 반응 토글과 조회 분리, 키보드·모바일·스레드, 실패 재시도, 이름 변경·탈퇴 처리, 비공개 사진 경로와 동시 반응을 검사합니다.

`scripts/test/reaction-toggle.integration.mjs`는 명시적으로 허용된 로컬·CI MongoDB에서 임의 이름의 격리 DB만 만듭니다. 실제 저장소 어댑터로 20명 동시 추가·취소, 중복 데이터의 참여자·순서 보존과 달러 기호 리터럴을 검증하고 자기 격리 DB만 정리합니다. 운영 환경 파일이나 다른 DB 주소에서는 실행을 거부합니다.

main 병합과 운영 배포 전에는 기능 완료로 처리하지 않습니다. 공개 설치 파일 업데이트는 별도 릴리스 단계입니다.
