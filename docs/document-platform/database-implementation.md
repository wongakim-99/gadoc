# 데이터베이스 구현 상태

기준일: 2026-10-27. **전체 기능 목표는 진행 중이며, 노션 데이터베이스 전체 구현 완료 상태가 아니다.**

## 기능 범위의 기준

기존 [전체 분석](../notion-analysis/02-databases-properties-formulas.md)의 식별자를 [구현 추적표](database-coverage.json)로 연결했다. 표뿐 아니라 본문의 식별자도 포함한다. 기능군에 코드가 있어도 그 안의 모든 동작이 같지 않으면 `partial`로 유지한다. 공개 문서 분석과 실제 Notion 계정에서의 동작 관찰은 구분한다.

최신 확인 출처: [속성](https://www.notion.com/help/database-properties), [보기·필터·정렬](https://www.notion.com/help/views-filters-and-sorts), [관계·롤업](https://www.notion.com/help/relations-and-rollups), [자동화](https://www.notion.com/help/database-automations), [폼](https://www.notion.com/help/forms). 기존 분석의 개별 출처와 재현 시나리오를 함께 사용한다.

## 현재 구현

- 문서 영역 → **데이터베이스 · 지식베이스**에서 생성·탐색한다. 기존 문서를 추가하거나 새 페이지를 만든다. 행은 원본 문서를 참조하며 제목 클릭/옆에 열기를 구분한다.
- 기본 담당자·상태·검토일과 텍스트, 숫자, 선택, 다중 선택, 체크박스, URL, 날짜, 관계형, 롤업 속성을 추가한다. 속성 ID를 유지하면서 이름을 바꾼다.
- 담당자는 페이지에 접근할 수 있는 팀 멤버 중에서 검색하고 복수 선택한다. 공유된 읽기 전용 멤버도 지정 대상이다. 새 담당자에게 알림을 보내고 `@ 호출`로 확인을 요청할 수 있다.
- 담당자 지정은 접근 권한을 추가하지 않는다. 팀에 속하지 않은 이메일 기반 페이지 초대는 아직 별도 구현이 필요하다.
- 관계는 다른 데이터베이스의 문서에 대한 복수 참조다. 롤업은 연결 개수·숫자 합계·평균·최소·최대를 계산한다. 이는 임의 SQL JOIN 엔진이 아니다.
- 표·상태 보드, 제목 검색, 담당자·상태 필터, 제목·검토일 정렬을 제공한다. 현재 보기 설정을 이름 붙여 저장하고 URL로 다시 연다.
- 문서를 열면 제목 아래에 소속 데이터베이스의 속성을 표시하고 직접 편집한다. 변경된 대상 값을 다시 조회하면 관계를 통한 집계에 반영된다.
- 셀 입력은 포커스 이동/Enter 때 저장한다. 선택형 값은 즉시 저장한다. 실패 시 텍스트 초안을 유지하고 선택형 값은 원래 값으로 되돌린다. 저장 전 이동을 보호한다.
- revision 기반 조건부 갱신으로 충돌 시 409를 반환한다. 새로고침으로 다른 변경을 확인한 뒤 다시 저장한다.

## 모델과 권한

`knowledge_databases`는 현재 속성과 저장된 보기를 담고, `knowledge_database_rows`는 문서 ID와 속성 값을 담는다. `(teamId, databaseId, documentId)` unique 인덱스로 중복 추가를 막는다. 팀 경계를 모든 쿼리에 적용한다.

문서의 현재 열람·편집 권한을 사용한다. 관계 대상 및 집계도 같은 열람 범위로 필터링한다. 숨겨진 문서의 ID·제목·집계 개수를 반환하지 않는다. 보이지 않는 관계를 사용자가 편집 과정에서 우연히 제거하지 않도록 보존한다. 알림 본문은 원문 제목을 복제하지 않는다.

## 전체 목표에서 남은 작업

범위를 줄인 것이 아니라 아직 구현하지 않은 항목이다. 상세 판정은 추적표를 기준으로 한다.

- 데이터베이스 컨테이너·데이터 소스·링크된 보기의 별도 식별자, 다중 소스와 소스 이동/복제/휴지통/복원
- 속성 삭제·순서·숨김·타입 전환과 이관, 서식 있는 텍스트, 숫자 표시 형식, 날짜 기간/시간대/리마인더, 상태 그룹
- 파일, 이메일, 전화, 생성·수정 메타데이터, 고유 ID, 장소, 소유자·검증, 조건부 색상과 속성 댓글
- 양방향 관계, 개수 제한·관계 표시 속성, 전체 롤업 연산 및 수식 언어·함수·의존성·오류 처리
- 목록·갤러리·달력·타임라인·차트·지도·피드·대시보드·폼, 각 뷰의 고유 상호작용
- 중첩 AND/OR 필터, 복수 정렬, 임의 그룹·하위 그룹, 열 집계, 저장 뷰 수정/삭제·개인/공유 설정
- 하위 항목·의존성·날짜 이동, 템플릿·반복 템플릿, 레이아웃 편집
- 버튼·자동화·예약·웹훅·외부 연결·AI 속성, 실행 이력과 실패 복구
- 팀 밖의 페이지 공유 초대, 세밀한 DB/소스 권한, 잠금, 감사 및 변경 이력
- 가져오기/내보내기, 커서 페이지네이션·가상화·대량 편집, 백업/복구와 부하 검증

현재 상한은 속성 50개, 저장 보기 50개, 배열 값 100개다. 전체 행을 조회하므로 대용량 운영 성능을 보증하지 않는다. 알림은 기존 이벤트 리스너를 사용하며 영속 outbox 재시도까지 구현한 상태는 아니다. 독립 브라우저의 실시간 셀 공동 편집은 아직 지원하지 않으며 새로고침으로 변경을 읽는다.

## 검증 및 반영

`tests/e2e/knowledge-database.e2e.spec.ts`는 실제 Mongo/API로 생성, 담당자, 공유 멤버 호출/알림, 관계·롤업, 저장 보기/이름 변경, 문서에서 속성 수정, 실패 초안, 읽기 전용·비공개·충돌, 모바일 레이아웃을 검증한다. 대시보드와 워크스페이스의 주요 색상 토큰도 비교한다.

커밋·반영 절차는 [CONTRIBUTING](../../CONTRIBUTING.md)을 따른다. 전체 완료 게이트 미충족 상태에서 `dev`/`main` 병합을 먼저 진행하지 않는다.

### 2026-10-27 본문 블록 전환 진행

문서의 `/데이터베이스`·`/database` 메뉴로 본문에 데이터베이스 블록을 삽입하고 새로 생성하거나 기존 데이터베이스를 연결할 수 있다. 편집 및 읽기 모드에서 동일한 스키마로 렌더링한다. 인라인 보기 전환은 부모 문서 URL을 변경하지 않는다. 생성·행 추가·저장·재접속 E2E를 통과했다. 블록별 독립 보기의 영속화와 전체 페이지/인라인 전환 등은 아직 미완료이며 Notion 전체 동등성을 의미하지 않는다.


### 본문 블록의 독립 보기·페이지 편집

각 본문 블록의 `viewState`에 보기 이름/복제/삭제/활성 보기/검색/필터/정렬과 블록별 속성 표시 설정을 저장한다. 동일 데이터베이스를 연결한 두 블록의 보기 설정은 독립적이다. 표의 새 페이지는 바로 행을 생성하고 이름 입력에 포커스하며 이름 변경은 자동 저장한다. 열기는 부모 페이지를 유지하며 기존 분할 패널을 사용한다.

행·속성 변경은 같은 브라우저의 연결 블록과 분할 화면에 알리고 각 화면이 인증된 API로 조회한다. 이는 서버 기반 다중 사용자 실시간 동기화가 아니다. 저장 실패 시 제목 초안을 유지하고 페이지 전환을 차단한다. 브라우저 테스트는 콘솔 오류, 두 블록의 독립 보기 유지, 이름 변경, 옆 화면 열기도 검사한다.

전체 속성 편집 메뉴, 보기별 열 배치/너비, 모든 보기 종류, 인라인↔전체 페이지 변환 및 전체 Notion 기능 동등성은 여전히 미완료다.


## 2026-10-27 추가 구현 — 전체 동등성은 미완료

- 수식 AST 평가와 안정적인 속성 참조, 목록 람다/변수, 계산 오류를 연결했다. 전체 Notion Formula 2.0 타입·페이지/사람 객체·서식·정규식 등은 아직 호환되지 않는다.
- AND/OR 조회, 다중 정렬, 목록/갤러리/달력/타임라인/기초 차트, 보드 속성 그룹 및 드래그, 보기별 속성 표시와 표 하단 계산을 구현했다. 달력/보드는 변경한 실제 셀을 저장한다.
- 속성 설정·삭제·복원, 구조 잠금, 관계 one/many와 18종 롤업을 연결했다. 속성 타입 변환 및 안정적인 선택 옵션 ID 전환은 미완료다. Formula/Rollup을 다른 롤업의 대상으로 삼는 기능은 현재 명시적으로 거절한다.
- `/row/:documentId` PATCH는 여러 속성을 모두 검증한 후 한 행을 원자적으로 변경한다. 생성 기본값은 최초 upsert에만 적용하며 재시도는 기존 값을 덮어쓰지 않는다. 필터 기본값은 확실한 AND 조건만 추론한다.
- 인증된 `/database` Socket.IO 알림과 재조회로 다른 브라우저 변경을 반영한다. 방송에는 팀 ID만 포함한다. 멤버십 및 토큰을 전송 시 재확인한다. 텍스트 셀은 작성 시작 버전으로 충돌을 검사하며 초안 보존 후 현재 값 사용/명시적 재저장을 제공한다. 단일 서버 이벤트 전달이며 다중 인스턴스 어댑터 및 분산 이벤트 전달은 추가 과제다.
- 템플릿 원본은 실제 문서와 `isTemplate` 행으로 관리한다. 일반 DB 행 목록에서는 제외하고 원본 페이지의 속성/본문을 편집한다. 생성 ID를 재사용해 재시도 중복 생성을 방지하며 문서 공유 설정도 원자적으로 복사한다. 반복/기본 템플릿, 하위 페이지 깊은 복제는 미완료다.
- 고유 ID의 숫자를 행에 영속 저장한다. 번호 예약은 DB별 원자 카운터를 사용하고 동시 보충은 이미 할당한 번호를 변경하지 않는다. 실패/경쟁으로 번호 사이 간격은 생길 수 있다. 접두사만 변경 가능하며 짧은 ID URL은 미구현이다.
- 현재 보기의 접근 가능한 행과 표시 속성을 CSV로 내려받는다. CSV의 스프레드시트 수식 실행을 방지하며 관계/사람은 표시 이름을 사용한다. 데이터 모델 전체 복원/CSV import/하위 페이지 export는 미구현이다.

검증 파일은 `tests/e2e/database-*.e2e.spec.ts` 및 `knowledge-database.e2e.spec.ts`에 있으며 공식 제품과의 런타임 대조 검증을 대신하지 않는다. 범위 장부의 `partial`은 기능 일부와 검증 근거가 있다는 의미이며 전체 기능 완료 비율이 아니다.


### 배치/원본 분리 및 공유 범위 후속
컨테이너 API는 `/team/:teamId/database-container`, 원본 스키마/행 API는 기존 `/team/:teamId/database`를 유지한다. 새 배치는 별도 ID를 사용하며 원본 소스 ID 목록만 보관한다. 기존 블록은 ID를 바꾸지 않고 호환 wrapper로 연다. 다중 원본 연결/선택/해제와 요청 ID 재시도를 지원한다. 연결 해제는 원본 삭제가 아니다. 보기 객체의 전체 container 이전, 소스 이동/휴지통은 아직 미완료다.

본문에 생성한 소스는 상위 문서 접근 범위를 적용한다. 새 행/템플릿 및 새 하위 문서는 동적 부모 권한 검사로 공유 취소를 반영한다. 레거시 문서의 권한은 일괄 변경하지 않는다. 팀 목록과 관계 집계도 원본 접근 범위를 적용하며 접근 권한을 잃은 웹 DB 화면은 비운다. Notion의 모든 공유 예외와 동등하다는 의미는 아니다.


## 양방향 관계·기본 템플릿·열 배치 후속
- 이전 전체 브라우저 회귀 22개 통과. 이후 양방향 관계 E2E 1개, 기본 템플릿/기존 템플릿 2개, 열 배치 1개 및 기존 inline 2개 통과.
- 관계를 원본 행 한 곳에 저장하고 반대쪽 속성은 파생 조회한다. 반대쪽 셀 편집은 원본 행의 CAS 변경으로 반영하며 롤업도 갱신된다. 이전 관계 버전 수정은 409, 원본 속성 archive/restore에 따라 반대쪽 속성도 사라지고 복구된다. 역방향 여러 항목 일괄 변경과 파생 속성을 롤업 대상으로 쓰는 기능은 아직 제한된다.
- 소스 기본 템플릿 설정/해제, 새 페이지 본문/속성 적용, 필터 기본값 우선 적용, 템플릿 제거 시 기본 설정 해제. 생성 재시도는 편집된 기존 값을 덮어쓰지 않는다. 보기별 기본 템플릿/반복 생성은 남았다.
- 표의 열 너비를 포인터/키보드로 변경하고 열 순서를 조정한다. 인라인 블록의 보기별 설정으로 자동 저장되며 다른 블록에 영향을 주지 않는다. 새로고침 보존 E2E 통과. 저장된 전체 페이지 보기의 갱신/자동 저장은 후속 작업이다.
- 최신 서버 빌드 및 웹 TypeScript 통과. 위 추가 변경 이후 전체 단위/브라우저 회귀는 재실행 필요. 전체 기능 완료나 Notion과 동일함을 선언하지 않는다.


## 사용자 검토 반영: 기능 나열형 화면 중단, 문서 안 작업 흐름 우선
사용자가 공식 한국어 데이터베이스 소개/데이터베이스/보기 카테고리를 제공하고 화면의 옵션·설정 과다 노출을 지적했다. 전체 기능 범위는 유지하되 새로운 기능 확장보다 현재 표면의 레이아웃과 직접 편집 흐름을 먼저 수정한다.

- https://www.notion.com/ko/help/intro-to-databases
- https://www.notion.com/ko/help/category/databases
- https://www.notion.com/ko/help/category/database-views
- 공식 소개의 메뉴 이미지 다운로드 후 실제 시각 비교. 구현은 이미지 복사가 아니라 서비스 컴포넌트로 수행.
- 보기 탭/추가, 조회 도구, 보기 옵션, 새 페이지·템플릿을 한 줄에 배치. 소스/열/가져오기/잠금 등은 옵션 팝오버로 이동.
- 표 마지막 열에서 속성 추가, 마지막 행에서 페이지 추가. 생성 후 제목 즉시 포커스, 별도 제목 생성 폼 제거. 헤더 클릭은 해당 속성 편집기로 직접 연결.
- 새 표 기본 열 너비 축소, 빈 셀의 드롭다운 마커와 과도한 설명/중복 컨트롤 제거. 전체 페이지/인라인의 조작 구조 통일.
- API 및 저장 기능은 유지. 기존 E2E도 변경된 실제 사용자 경로에 맞춰 업데이트 중. 26개 회귀 통과는 이 레이아웃 변경 이전 결과이다.
- CSV 파서3개 및 실패 행 재시도 브라우저 검증 통과. CSV 담당자/관계 재연결, 고급 차트 등은 여전히 미완료. 차트 확장 초안은 사용자 지적에 따라 미통합 상태로 제거했다.


## 화면 단순화 검증 결과
- 변경된 메뉴 경로로 DB·문서 slash 브라우저 회귀 28개 통과 (`.rea/database-refined-final-check`). 이후 기본 보기 자동 저장/저장 실패 명시적 재시도까지 확장하고 관련 6개 브라우저 테스트 통과 (`.rea/database-default-view`).
- 전체 페이지도 첫 화면의 기본 보기를 바로 자동 저장한다. 보기 생성/저장 선행 단계가 필요하지 않다. 마지막 보기는 삭제를 거부한다.
- 담당자/관계/다중 선택은 셀의 팝오버로 열려 행 높이를 늘리지 않는다. 열 제목에서 직접 편집, 템플릿은 새 페이지 버튼의 화살표, 계산 선택은 열 하단 hover/focus에 노출.
- 사용되지 않는 별도 생성/이름변경 폼과 중복 속성 표시 설정을 제거했다. 기본 폭으로 3개 속성과 속성 추가가 문서 너비에 들어가도록 조절했다.
- 최신 웹 단위 88개, TypeScript 통과. 최신 서버 빌드 통과. 이미지: `docs/design-system/assets/database-surface-refined.png`. 공식 이미지와 비교한 화면 개선이며, 전체 제품 런타임 동등성 검증 완료가 아니다.
- 전체 범위는 계속 in_progress. 반복 템플릿/폼/자동화/하위 항목 등은 남았고 출시 조건은 충족되지 않았다. 커밋/푸시/PR/merge는 아직 수행하지 않았다.


## 항목 문맥 메뉴
행 우클릭/hover 메뉴에서 페이지 열기·이름 변경·링크 복사·복제·휴지통 이동을 제공한다. 복제 API는 본문/편집 가능한 일반 속성과 원본 접근 경계를 보존하고 새 고유 ID를 발급한다. 재시도는 동일 페이지를 재사용한다. 삭제는 기존 문서 휴지통으로 연결하고 복원 시 원래 행 ID/속성/고유 번호를 유지한다. 브라우저 검증1개 통과. 중첩 하위 페이지·블록 내부 데이터의 깊은 복제 및 행 이동은 남아 있다.


## 직접 편집 UX 후속: 기본값과 보기 생성
- 공식 참고: https://www.notion.com/ko/help/intro-to-databases , https://www.notion.com/ko/help/category/databases , https://www.notion.com/ko/help/category/database-views . 공개 문서/이미지를 기준으로 수정했으며 Notion 인증된 런타임과 완전 동등성 검증은 아직 하지 않았다.
- UI로 만드는 새 데이터베이스는 이름 열부터 시작한다. 담당자/상태/검토일을 강제로 미리 만들지 않는다. 기존 데이터베이스 속성은 보존한다.
- 기본 정렬을 입력 순서로 변경했다. 기존 저장 정렬은 유지한다. 수동 행 순서 드래그 저장은 아직 미구현이다.
- 필터, 정렬, 검색을 별도 팝오버로 분리했다. 보기 추가는 종류/이름만 고르는 전용 창에서 생성 후 즉시 전환한다.
- 빈 데이터베이스의 보드/달력/타임라인은 필요한 상태/날짜 속성을 준비한다. 기존 적합 속성이 있으면 재사용한다. 속성 생성과 보기 생성은 별도 요청이므로 보기 저장 실패 시 생성 속성은 남을 수 있다.
- 첫 추가 보기 생성 시 가상 기본 표를 함께 영속화해 기존 표 탭이 사라지지 않게 수정했다. 기존 기본 보기 자동 저장과 마지막 보기 삭제 방지도 유지한다.
- 변경 핵심: DatabaseWorkspace.tsx, database.service.ts, database-saved-view.e2e.spec.ts, database-view-defaults.e2e.spec.ts. 기존 표면 변경은 DatabaseMenu/DatabaseCell/DatabaseRowActions/DatabasePropertyIcon 등에 반영되어 있다.
- 검증: 서버 빌드, 웹 TypeScript, 서버 단위 130개/37 suite, 웹 단위 88개/26 file 통과. 빈 DB→보드→달력 생성/자동 속성/표 탭 유지/새로고침, 저장 보기 재시도 테스트 3개 통과. 전체 브라우저 회귀 결과는 아래에 별도 기록한다.
- 남은 범위: 전체 Notion 기능/시각/동작 동등성, 반복 템플릿/자동화/폼/하위 항목/의존성/고급 차트/전체 수식 및 대규모 데이터 성능. 생산 웹 빌드와 파일 업로드 런타임은 이번 검증에 포함하지 않았다. 커밋/푸시/PR/merge는 수행하지 않았다.

- 최신 전체 브라우저 회귀: 31/31 통과 (1.5분), `.rea/database-ux-final-regression`. 최신 설정 메뉴 분리/보기 생성/자동 속성 준비를 포함한다.
