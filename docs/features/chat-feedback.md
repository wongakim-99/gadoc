# 채팅 피드백과 알림 삭제

## 반응 선택

반응 옆의 작은 `+` 문자를 `리액션 추가` 아이콘 버튼으로 바꿉니다. 메시지 메뉴와 답글에서도 같은 선택창을 사용합니다. 기본 이모지는 100개 이상의 이름 있는 로컬 목록이며, 추천·표정·손짓·축하·상태·자연으로 분류합니다. 한국어, 영어 별칭과 이모지 자체를 검색할 수 있습니다. 외부 서비스에 대화나 검색어를 전송하지 않습니다.

선택창은 스크롤 영역 밖의 포털에서 화면 가장자리에 맞춰 위치를 바꿉니다. 위치가 잡힌 뒤 검색창에 포커스를 주고, 화살표로 이동하고 Enter로 선택할 수 있습니다. Escape·닫기·바깥 클릭은 반응을 추가하지 않습니다. 기존 반응 버튼은 그대로 추가·취소를 담당하고, 참여자 조회는 별도입니다. 커스텀 스티커 업로드·제작은 이 기본 선택창과 별도 범위입니다.

## 채널 참여자

채널 오른쪽 위의 사람 아이콘과 숫자로 이름 검색 가능한 목록을 엽니다. 공개·음성 채널은 접근 가능한 워크스페이스 멤버, 비공개·DM·그룹 대화는 해당 방의 멤버만 표시합니다. 이메일이나 내부 식별자는 표시하지 않으며, 현재 접속 인원인 것처럼 표시하지 않습니다. 기존 비공개 사진 경로만 요청하고 실패하면 이니셜을 표시합니다.

이 목록은 조회 기능입니다. 채널 멤버 추가·제거, 실제 온라인 상태, 워크스페이스 가입 관리 전체를 완료했다는 의미는 아닙니다.

## 새 메시지·수정·스레드의 언급

세 입력 화면에서 커서 위치 기준으로 같은 대상 검색과 키보드 처리를 사용합니다. 후보 선택을 위한 Enter는 메시지를 전송하거나 수정 저장하지 않습니다. 전체 후보는 `@all`로 삽입하며 `@everyone`, `@channel`, `@전체`도 서버에서 해석합니다. 이메일과 URL 속 `@`는 언급으로 해석하지 않습니다. 공백이 없는 사용자 이름 기준이며, `@here`의 접속자 한정 동작은 제공하지 않습니다.

서버는 작성자의 팀·방 접근 권한과 보관 상태를 확인합니다. 비공개 방의 명시적 언급과 전체 언급은 그 방의 멤버에게만 전달합니다. 삭제된 계정과 본인은 제외합니다. 답글의 부모는 같은 팀·채널에 있어야 합니다.

편집할 때 본문과 언급 ID를 같은 MongoDB 업데이트로 저장합니다. 읽은 본문이 그 사이 바뀌면 충돌로 거절하며, 저장 실패 시 작성 초안을 남깁니다. 저장에 성공한 뒤 새로 추가된 수신자에게만 알림을 보냅니다. 동일 내용 저장이나 기존 언급을 유지하는 본문 수정으로 알림을 반복하지 않습니다. 언급 제거는 과거 알림을 삭제하지 않습니다. 부모 작성자를 명시적으로 언급한 답글에는 같은 사람에게 별도의 답글 알림을 중복 발송하지 않습니다.

## 알림 전체 삭제

브라우저 시스템 확인창 대신 공통 앱 확인 모달을 사용합니다. 처음에는 취소 버튼을 선택하고, 취소·Escape는 삭제하지 않습니다. 처리 중에는 중복 요청과 닫기를 막고 실패 시 모달 안에서 오류·재시도를 제공합니다. 서버 응답 성공 전에는 목록을 비우지 않습니다. 삭제 범위는 현재 워크스페이스의 본인 알림이며 원본 메시지·문서·이슈는 유지됩니다. 이전 워크스페이스의 지연 응답은 새 워크스페이스 목록을 바꾸지 않습니다.

방별·기능별 알림 수신 설정과 제품 전체 업데이트 공지는 별도 기능입니다. 이 변경만으로 해당 설정이 제공되는 것은 아닙니다.

## 검증과 배포

`chat-feedback-polish.e2e.spec.ts`는 검색·키보드·포커스 복원·모바일 화면 경계, 공개/비공개 참여자, 본문/답글 편집과 실제 언급 저장·알림, 실패 시 초안 보존, 알림 삭제 모달의 취소·중복 방지·실패·재시도를 검증합니다. 기존 `thread-actions-theme.e2e.spec.ts`는 새 선택창을 통한 답글 반응과 기존 편집·삭제·테마를 함께 검증합니다.

서버·웹을 함께 배포해야 편집 후 언급 ID와 알림이 일치합니다. main 병합, CI와 실제 운영 revision 확인 전에는 운영 반영 완료로 처리하지 않습니다.
