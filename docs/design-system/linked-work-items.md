# 대화에서 실행으로: 이슈와 자료 연결

브랜치: `feature/linked-work-items`. 로컬 검토 단계이며 원격 게시/PR은 수행하지 않았다.

## 사용 흐름

1. 메시지의 **이슈 연결**에서 **이 메시지에서 이슈 만들기**를 선택한다. 대화를 유지하며 오른쪽 작업 영역에서 작성한다. 원문은 생성 근거로 저장한다.
2. 생성에 성공하면 같은 작업 영역에서 이슈 상세로 전환한다. 오른쪽 영역 안에 별도의 배경 모달을 겹치지 않는다. 저장 후에도 상세 화면을 유지한다.
3. 연결 카드의 **제목**은 현재 영역에서 열고, **옆에 열기**는 분할 영역에서 연다.
4. **자료 연결 / 이슈 연결**은 검색 가능한 선택 모달을 연다. 항목 선택 후 **연결하기**로 확정하며 실패 시 선택을 유지한다. 성공 안내와 새로 추가한 관계의 취소를 제공한다.
5. 문서·메시지·이슈 아이콘을 관계 영역으로 끌어 연결할 수 있다. 본문에 놓으면 본문 링크를 삽입한다.
6. 기존 ‘참조 준비 → 참조 넣기’는 연결 메뉴의 **다른 본문에 링크 넣기**로 이동했다. 기본 열기/자료 관계 흐름과 구분한다.
7. **해제**는 관계만 제거한다. 원본은 유지한다. 이미 존재한 관계에는 새 연결 취소를 표시하지 않아 기존 생성 근거가 지워지지 않게 한다.

작성 실패는 초안을 유지한다. 취소와 분할 종료는 미저장 변경을 확인한다. 선택 모달은 최상단 모달만 키보드를 처리하며 닫으면 포커스를 돌려준다.

## 저장 및 접근 모델

- 이슈의 `links`에 `{kind: document|message, resourceId, relation: origin|reference}`만 저장한다. 생성 근거는 이슈와 하나의 MongoDB document로 저장되어 부분 생성 실패를 피한다.
- 이슈 단위 최대 50개. 동일 종류/ID의 추가는 원자적 조건부 append로 중복을 방지하며 기존 origin을 reference로 바꾸지 않는다.
- 이슈 목록 응답에 raw links를 포함하지 않는다. 별도 조회에서 요청자의 현재 팀 역할, 문서 canView/아카이브, 메시지 채널 멤버십을 검사하고 허용된 자료만 제목/URL과 함께 반환한다.
- 비공개·제한·삭제·아카이브 자료는 제목/ID/숨긴 개수를 반환하지 않는다. 원문의 접근 권한을 이슈 생성으로 확장하지 않는다. 이슈 자체는 기존 팀 전체 공개 정책을 유지한다.
- 문서/메시지의 역방향 목록은 동일한 links를 조회한다. 제목/상태를 복제하지 않고 이슈 원본을 읽는다. 최신 변경순 최대 100개이며 한도 안내를 표시한다.
- 같은 분할 작업 공간에서는 기존 `slacord:issues-refresh` 이벤트로 갱신한다. 다른 창/사용자 변경은 포커스 복귀 및 보이는 화면에서 30초 주기로 반영한다. WebSocket 기반 즉시 관계 동기화는 이번 범위가 아니다.
- 메시지 관련 목록은 후속 업무 패널을 연 경우에만 조회한다. 모든 메시지마다 요청하지 않는다.
- 기존 이슈 수정/삭제도 route teamId와 실제 이슈 소속을 검사한다.

## API

| 요청 | 역할 |
|---|---|
| POST `/team/:teamId/issue` + `sourceMessageId?` | 검증한 원문과 이슈 동시 생성 |
| GET `/team/:teamId/issue/related?kind&resourceId` | 문서/메시지의 연결된 이슈 |
| GET `/team/:teamId/issue/:issueId/links` | 접근 가능한 근거/참고 자료 |
| POST `/team/:teamId/issue/:issueId/links` | `{kind, resourceId}` 연결, `{links, created}` 반환 |
| DELETE `/team/:teamId/issue/:issueId/links?kind&resourceId` | 관계 해제 |

모든 경로는 인증 및 팀 멤버 권한을 요구하며 쓰기는 guest에게 허용하지 않는다. ID와 종류를 DTO에서 검증한다.

## 검증

- 서버/웹 TypeScript, 서버 빌드 통과.
- 서버 단위 121개(36 suites), 웹 단위 81개(23 files) 통과.
- 신규 실제 API/브라우저 2개: 생성 실패 후 재시도, 원문 저장, 문서 연결, 상태 반영/새로고침, 해제, 비공개/권한 변경/게스트/다른 팀/잘못된 ID, 동시 중복 추가와 아카이브 검증.
- 기존 연결/문서/드래그 브라우저 18개 통과.
- 캡처는 합성 로컬 자료만 사용했다. [검토 화면](assets/linked-work-items.png).

## 남은 범위

프로젝트·서비스 공간, [문서 DB의 전체 기능](../document-platform/database-implementation.md), 다대다 일반 관계 모델, 결정 기록/공지 자동 연결, 알림·관계 감사 이력, 페이지네이션, 삭제 자료 관계 정리, WebSocket 관계 이벤트는 후속 작업이다. 과거 Markdown/문서 링크를 자동 관계로 이관하지 않는다. 기존 드래그 본문 삽입은 본문 링크이며, 관계 패널에 놓는 동작과 구분한다.

로컬 파일 저장소는 이전 실행과 같이 미기동 상태다. 이번 검증은 파일 업로드 성공을 포함하지 않는다.
