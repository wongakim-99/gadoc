# Slacord 디자인·협업 흐름 개선 방향

조사일: 2026-10-26 · 상태: 제안, 제품 적용 전 · 대상: 웹/데스크톱/모바일 공통 작업 공간

> 사용자 검토 결과 이 문서와 v1 시안은 색상·배치 탐색에 불과하며 UX 완성안이 아니다. 회의·문서·데이터베이스 통합의 기준과 구현 순서는 [통합 UX 설계 v2](integrated-workspace-ux.md)가 우선한다. 팔레트와 비주얼 디자인은 미확정이다.

## 권장 방향

**대화의 맥락을 문서와 실행할 일까지 이어주는 팀 워크스페이스**로 정리한다. 제품 기능을 계속 확장하되 화면은 현재 업무에 필요한 대상부터 보여준다. 기존 갈색·금색 팔레트를 교체하고, 밝은 중립색과 블루를 기본안으로 제안한다. 다크 모드는 같은 의미의 토큰을 사용하는 동등한 테마로 제공한다. 색상 선호는 사용자 검토 전이며 확정하지 않았다.

현재는 홈·채팅·문서·이슈·공지라는 도구 종류가 탐색의 중심이다. 제안은 개인 영역(받은함·내 작업)과 팀 공간을 구분하고, 공간 안에서 대화·문서·이슈를 전환하는 구조다. 모든 기존 자료를 찾을 수 있는 전체 채널/문서/이슈 탐색도 유지한다. 공간에 속하지 않은 자료를 숨기거나 자동 이동하지 않는다.

## 확인한 현재 제품과 문제

README, 실제 프런트엔드와 서버 도메인 모델을 확인했다. 기존 Graphify 그래프는 문서 백엔드 중심이므로 전체 제품의 기능 근거로 확장 해석하지 않았다.

| 현재 근거 | 관찰 | 개선 방향 |
| --- | --- | --- |
| `WorkspaceSidebarShell.tsx` | 서비스 로고·팀·검색·알림·기능 메뉴·현재 영역 목록이 한 세로축을 공유 | 브랜드는 작게, 팀 전환은 명확하게. 개인 작업과 팀 자료의 구획을 구분 |
| `globals.css` | 중립색 workspace 덮어쓰기와 기존 갈색 브랜드 토큰이 공존 | light/dark 의미 토큰을 원본으로 삼고 화면별 덮어쓰기 제거 |
| `IssueModalFields.tsx`, `SidebarNavLink.tsx`, `HuddlePanel.tsx` | 직접 지정된 색상, 흰 글씨, 서로 다른 배경 | 모달·배지·통화 패널까지 토큰 적용 범위 포함 |
| `DocumentEditorPanel.tsx`, `BlockEditor.tsx`, `DocumentLoading.tsx` | dark 테마 고정 | 에디터와 skeleton까지 선택한 테마를 따르게 변경 |
| `channel.entity.ts`, `issue.entity.ts` | 팀 소속은 있으나 공간/프로젝트 ID와 문서 연결 필드 없음 | 공간 탐색은 신규 관계 모델이 필요한 기능. 메뉴만 바꿔 구현 완료로 처리하지 않음 |
| `document.entity.ts` | parentId, 개별 열람/편집 정책 존재 | 문서 계층 유지. 이동·상속·관련 자료 표시 전에 서버 권한 검증 정리 |
| `notification.entity.ts` | 멘션·이슈 배정/변경·스레드 답글, 읽음 상태 존재 | 기존 이벤트로 받은함부터 구성. 문서 검토 요청·미루기는 신규 이벤트/상태 필요 |
| 현재 README의 허들 | WebRTC Mesh, 소규모 4명 이하 | 연결 상태와 탐색 중 지속되는 제어 개선. 대규모 음성 서비스 확장은 별도 설계 |

## 개별 레퍼런스에서 가져올 것

공식 도움말과 제품 디자인 글을 조사했다. 로그인한 경쟁 제품에서 전 기능을 직접 테스트한 조사는 아니다. Linear의 공식 전후 비교 이미지도 시각 확인했다. 아래 적용안은 자료를 바탕으로 한 Slacord 설계 제안이다. 브랜드 자산이나 비공개 소스를 복사하지 않았다.

| 레퍼런스와 출처 | 확인한 패턴 | Slacord 적용 | 그대로 도입하지 않을 부분 |

| [Slack 채널/DM 탭](https://slack.com/intl/en-gb/help/articles/32562841868307-Add-and-manage-tabs-in-channels-and-direct-messages) | 대화 안에서 canvas·list·자료를 탭으로 연결 | 채널에 관련 문서·이슈 뷰 연결, 자료를 찾으러 영역을 반복 이동하는 비용 축소 | 탭을 무제한 노출하거나 권한 없는 문서를 제목만 표시하지 않음 |

| [Linear 2026 디자인 개선](https://linear.app/now/behind-the-latest-design-refresh) | 탐색의 시각적 무게를 낮추고 헤더 제어 위치를 일관되게 정리 | 위치 헤더/뷰 제어를 분리, 보조 아이콘 절제, 본문 중심 대비 | 작은 글씨와 고밀도 화면을 모바일까지 그대로 축소하지 않음 |
| [Linear 받은함](https://linear.app/docs/inbox) | 확인해야 할 업데이트, 읽음/미루기, 대상 문맥에서 처리 | 멘션·내 담당 이슈 우선 받은함, 맥락을 확인하는 우측 패널 | 모든 수정 이벤트를 같은 중요도의 빨간 배지로 표시하지 않음 |

## 공간별 역할과 레이아웃

| 영역 | 역할 | 기본 규격/행동 |
| --- | --- | --- |
| 좌측 상단 | 작은 브랜드 식별, 실제 팀 이름과 전환 | 로고는 내비게이션을 지배하지 않음. 워크스페이스 전환을 로고 클릭만으로 숨기지 않음 |
| 좌측 개인 영역 | 전체 검색·받은함·내 작업 | 어느 화면에서든 같은 위치. 배지는 나에게 필요한 이벤트 위주 |
| 좌측 중간 | 즐겨찾기·팀 공간·공간 내 자료 | 240–264px, 행 36px. 문서 계층은 같은 부모/자식 의미 유지 |
| 상단 첫 줄 | 현재 위치·공유 범위·주요 동작 | 약 56px. URL로 복원 가능한 위치와 뒤로가기 지원 |
| 상단 둘째 줄 | 현재 공간의 대화·문서·이슈, 뷰/필터 | 약 44px. 개인 받은함에서는 받은함 필터로 교체; 시안은 비교 편의를 위해 공간 탭을 유지 |
| 본문 | 대화·작성·업무 처리 | 문서 720–880px 읽기 폭, 채팅/보드는 가용 폭. 모든 영역을 카드 안에 넣지 않음 |
| 우측 패널 | 스레드·관련 문서·이슈·속성의 보조 확인 | 360–440px. 주 작업을 가리지 않도록 한 번에 하나, Esc/포커스 복귀 |
| 하단 통화 영역 | 연결 상태·음소거·화면 공유·나가기 | 통화 중에만 고정. 화면 이동에도 세션 유지 |
| 모바일 | 단일 주 작업 + 탐색 drawer | 주요 터치 영역 44px 목표, 대화↔문서 이동 후 스크롤/초안 복원. 가로 보드는 보드 안에서만 스크롤 |

워크스페이스가 많아졌을 때만 별도 전환 레일을 검토한다. Discord식 서버 레일과 Slack식 앱 레일, Notion식 문서 트리를 한 화면에 모두 병치하면 너비와 학습 비용이 과해진다.

## 색상 및 디자인 시스템

| 의미 | Cloud Blue (권장 기본) | Slate Dark | Quiet Teal (대안) |
| --- | --- | --- | --- |
| 본문 배경 | `#FFFFFF` | `#171B22` | `#FFFFFF` |
| 탐색 배경 | `#F6F7F9` | `#12161C` | `#F3F7F7` |
| 기본 글씨 | `#202733` | `#E9EDF4` | `#203232` |
| 보조 글씨 | `#606B7B` | `#A5AFBF` | `#526D6B` |
| 테두리 | `#E3E6EC` | `#353E4B` | `#DBE6E5` |
| 주요 동작/포커스 | `#2457D6` | `#99B7FF` | `#087770` |
| 선택된 배경 | `#EAF0FF` | `#253552` | `#E0F3F0` |

블루는 링크·선택·주요 동작에 사용하고 성공/오류/주의와 분리한다. 상태는 색과 텍스트/아이콘을 함께 쓴다. 채널마다 별도 강한 배경색을 부여하지 않는다. 빨강은 오류·파괴적 동작에 제한하고, 일반 읽지 않음에는 점/숫자를 쓴다.

실제품 토큰은 `surface.canvas/sidebar/raised`, `text.primary/secondary`, `border.subtle/strong`, `action.primary/hover`, `selection.background`, `status.success/warning/danger/info`, `focus.ring`으로 정리한다. `slack-*`, `discord-*` 같은 다른 제품명 기반 토큰은 단계적으로 제거한다. Next 루트와 포털에 동일 테마를 전달하고 BlockNote/Mantine 토큰도 연결한다.

기본 글씨는 14px, 문서 본문은 16px/1.8, 메타 정보는 최소 12px를 목표로 한다. 한글 지원 폰트를 함께 검증하고 라틴 폰트만 바꾸지 않는다. 시안은 설치된 시스템 폰트를 사용하며 폰트 최종안은 아니다. 간격은 4/8/12/16/24/32, 모서리는 제어 6px·패널 8–12px, 그림자는 떠 있는 레이어에 집중한다. 모션은 선택 100–140ms·패널 160–180ms 정도로 제한하고 reduced-motion에서는 제거한다.

## 기능 개선의 우선순위

| 순서 / 권장 feature 브랜치 | 구체적인 결과 | 선행 조건·완료 기준 |
| --- | --- | --- |
| 1 · `feature/workspace-theme` | 갈색/금색 제거, light/dark 전체 테마, 공통 헤더·제어·공백 재설계 | 채팅·문서·이슈·공지·설정·검색/모달·로딩/오류에 일관 적용. 저장/이동 회귀, 기본 글씨 대비 4.5:1와 제어 포커스 검증 |
| 2 · `feature/workspace-inbox` | 받은함, 나에게 배정된 이슈, 최근 문서·즐겨찾기 | 기존 알림 종류부터 적용. 즐겨찾기/최근 문서는 사용자별 저장; 접근권한 변경 시 제거/비노출 |
| 3 · `feature/context-links` | 채널 자료 탭, 메시지→이슈 생성, 이슈↔문서 연결 | 대상 타입/ID·팀 ID·원본 메시지 관계. 원본 삭제/권한 없음 처리, 생성 중복 방지, 서버 권한 검사 |
| 4 · `feature/team-spaces` | 업무별 자료 묶음, 공간별 개요/대화/문서/이슈 | Space/멤버십/리소스 연결 모델 검토. 기존 teamId/URL 유지, 미분류 자료 접근 및 점진 이관 |
| 5 · `feature/document-navigation` | 문서 이동·정렬·백링크·본문 하위 페이지 생성 | 서버 부모 권한·순환 방지·고아 문서·트랜잭션 정책 우선. 기존 자동 저장/실패 복구 유지 |
| 6 · `feature/issue-views` | 목록/보드 전환, 저장된 필터, 관련 이슈 | View 설정 버전·개인/공유 범위. 필터 결과가 같고 URL/뒤로가기로 복원 |
| 7 · `feature/huddle-context` | 탐색 중 지속되는 통화 제어, 통화 후 기록 연결 | 기존 통화 인원 범위, 연결/재연결/권한 거부 상태, 스크린리더·키보드 제어 |

노션 전체 블록·데이터베이스 속성·수식·관계·롤업·공동 편집·확장 기능 목표는 유지한다. 이 순서는 그 목표에 앞서 공통 UI와 연결 기반을 정리하기 위한 것이며, 전체 제품 범위를 축소한 목록이 아니다. 범용 데이터베이스와 기존 이슈 도메인은 관계/뷰 공유 여부를 설계하되 현재 API를 무조건 교체하지 않는다.

## 대표 흐름과 검증 시나리오

1. 팀 대화에서 요구사항 확인 → 원문을 연결해 이슈 생성 → 담당자 배정 → 받은함에서 확인 → 이슈 상세에서 결정 문서 열기. URL을 복사하면 접근 가능한 동료가 같은 대상에 도달해야 한다.
2. 문서 편집 중 관련 스레드 열기 → 답글 작성 → 문서로 복귀. 저장 실패 시 이동 때문에 편집 내용이 사라지지 않아야 한다.
3. 하위 문서 이동 → 접근 범위 변경을 명시 → 기존 링크와 검색 결과 점검. 다른 팀/권한 없는 부모/자손으로의 이동 요청을 서버에서 거부해야 한다.
4. 통화 중 채팅에서 문서로 이동 → 음소거 상태 유지 → 화면 공유 중단 → 종료 후 기록 열기. 연결된 척하는 UI와 실제 연결 상태가 달라서는 안 된다.
5. 모바일에서 받은함→이슈→관련 문서→뒤로가기. 읽던 위치와 입력 초안 복원, 페이지 전체 가로 넘침 없음.

사용성 검증은 처음 사용하는 사람에게 검색·하위 문서 생성·이슈 연결·알림 처리 과제를 주고, 도움 없이 완료 여부/오진입/되돌아가기 횟수를 기존 UI와 비교한다. 아직 사용자 테스트로 개선 효과가 입증된 상태는 아니다.

## 이번 산출물과 한계

- [클릭 가능한 시안](preview.html): 개요/대화/문서/이슈/받은함/내 작업/공지, 세 팔레트 전환, 검색, 대화→이슈 생성, 관련 자료 패널, 모바일 탐색.
- 합성 데이터와 메모리 상태만 사용한다. 편집/백엔드/실제 통화/권한 시스템은 이 시안에 구현하지 않았다. 새로고침하면 시안에서 추가한 항목은 초기화된다.
- 실제 서비스 소스는 변경하지 않았다. 시안은 `docs/design/`에 분리되어 제품 배포에 자동 포함되지 않는다.
- Playwright로 테마 3종, 대화→이슈, 문서 패널, 검색, 입력 문자 처리, 390px 모바일 탐색/넘침, reduced-motion, 콘솔 오류 부재 확인. 데스크톱/모바일 스크린샷 육안 검토.
- 화면/테마 후보와 기능 우선순위를 검토한 후 단계별 feature 브랜치로 적용한다. 현재 문서는 확정된 데이터 모델/아키텍처 결정이 아니다.
