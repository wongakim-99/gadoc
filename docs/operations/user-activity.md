# 사용자 가입과 워크스페이스 참여 기록

회원가입과 워크스페이스 참여는 별도 동작이다. 계정만 생성된 경우와 초대
참여가 거절된 경우를 구분할 수 있도록 HTTP 응답 종료 시 활동 기록을 남긴다.

## 기록 범위

- 회원가입, 로그인, 로그아웃, 현재 사용자 조회
- 워크스페이스 목록/상세 조회, 생성, 슬러그/초대 링크 참여
- 워크스페이스 정보 변경, 관리자에 의한 멤버 추가와 권한 변경
- 성공뿐 아니라 인증/권한 거절, 입력 오류, 요청 제한, 서버 오류, 연결 중단

`user_activity_events` 컬렉션에 `actorId`, `teamId`, `action`, `requestId`,
`statusCode`, `outcome`, `reason`, `durationMs`, `createdAt`을 저장한다.
인증되지 않은 요청은 `actorId: null`이며 사용자 ID를 추측하지 않는다.
로그인/가입 시도는 정규화한 이메일의 HMAC 식별값으로 연결한다. 해당 값은
이메일 원문이 아니며 JWT 서명 비밀이 바뀌면 식별값도 바뀐다.

비밀번호, 토큰, 쿠키, 초대 코드, 이메일 원문, 메시지/문서 내용, 요청/응답
본문, IP, 사용자 에이전트는 저장하지 않는다. 초대 경로는 `:code`로 대체한다.
예외 원문도 외부 장애 알림에 보내지 않고 요청 ID로 추적한다.

응답의 `X-Request-Id`로 서버 로그와 DB 기록을 연결한다. 오류 응답에도
`requestId`가 포함된다. 가드에서 거절된 요청은 인터셉터까지 도달하지
않으므로 응답의 `finish`/`close` 이벤트에서 중복 없이 수집한다.

## 조회와 보관

`GET /api/team/:teamId/access-events?actorId=<userId>&limit=50&before=<cursor>`

기존 로그인 쿠키 또는 Bearer 토큰을 사용한다. 해당 워크스페이스의 owner/admin만
조회할 수 있으며 다른 팀, 일반 멤버, guest는 접근할 수 없다. 응답은 기존 API
래퍼의 `data.items`, `data.nextCursor`를 사용한다. `limit`은 1~100이다.
인증 자체의 기록은 팀이 정해지기 전이므로 팀 API에 노출하지 않는다.
필요하면 권한이 있는 운영자가 DB에서 사용자 ID 또는 요청 ID로 조사한다.

30일 TTL 인덱스로 오래된 기록을 자동 정리한다. MongoDB TTL 삭제는 비동기이며
조회 API도 최근 30일로 제한한다. 기존 팀 내 운영 감사 기록은 변경하지 않는다.
기존의 누락된 과거 사용자 동작을 추측해 소급 생성하지 않는다.

DB 저장은 사용자 응답을 막지 않는 비동기 방식이며 동시에 200건으로 제한한다.
저장 실패/포화는 `activity_storage_failed`/`activity_storage_busy`와 요청 ID로
명시하고, 비밀정보를 제외한 이벤트는 서버의 구조화 로그에도 남긴다.
서버 로그의 외부 보관/회전 정책은 운영 환경에서 별도로 적용해야 한다.

## 검증

`pnpm test:server`는 인증 가드의 실패 응답, 로그 중복 방지, 관리자 권한과
민감정보 제외를 검사한다. `scripts/test/user-activity.integration.mjs`는
빌드된 전체 서버와 실제 MongoDB를 사용해 가입/로그인/초대 참여, DB 저장,
30일 TTL, 페이지 이동과 일반 멤버/외부 사용자 접근 거부를 검사한다.
CI의 `web-e2e` 작업에서 실행되며 테스트마다 임의 이름의 DB만 생성·삭제한다.
운영 URI나 `.env` 파일이 있는 작업 폴더에서는 실행을 거부한다.
