# 개인 프로필 이미지

GaDoc / Colding·kscold 독점 소스의 프로필 이미지 기능이다. 라이선스와 배포 정책은 변경하지 않는다.
이미지는 계정에 연결되며 모든 워크스페이스에 같은 이미지가 표시된다. 내 계정 설정에서 선택한 이미지를
미리 보고 저장하거나 현재 이미지를 삭제할 수 있다. 로그인 이메일의 표시 범위는 변경하지 않는다.

## API와 접근 범위

| 요청 | 동작 |
| --- | --- |
| `POST /api/auth/me/avatar` | 로그인한 본인의 이미지를 `file` multipart 하나로 업로드·교체함 |
| `DELETE /api/auth/me/avatar` | 로그인한 본인의 이미지 참조를 삭제함. 반복 요청도 성공함 |
| `GET /api/profile/:userId` | 본인 또는 현재 같은 워크스페이스 멤버의 identity를 조회함 |
| `GET /api/profile/:userId/avatar/:version` | 동일한 ACL로 현재 버전의 이미지만 제공함 |

변경 대상 ID와 이미지 URL을 입력하는 API는 없다. 추가 multipart 필드·복수 파일을 거절하며 서버가
외부 URL을 다운로드하지 않는다. 인증되지 않은 요청은 401, 읽을 수 없는 프로필과 지난 버전은 404다.
워크스페이스가 없는 계정도 자신의 이미지를 관리·조회할 수 있다. 다른 계정의 이미지를 읽으려면 현재
공유 워크스페이스가 있어야 하며, 이미지 URL을 아는 것만으로 권한이 생기지 않는다.

프로필 응답은 `id`, `username`, `avatarUrl`, `profileUpdatedAt`만 포함한다. 기존 `/auth/me`와
멤버 응답에는 캐시 동기화용 `profileUpdatedAt`을 추가한다. 새 identity 캐시는 이메일·비밀번호·토큰을
저장하지 않는다. 기존 메시지의 `authorId`를 현재 identity와 연결하므로 과거 메시지를 다시 쓰지 않아도
공통 Avatar가 변경된다. 사이드바, 계정, 채팅·스레드·반응 참여자, 멘션·이슈 담당자에 같은 Avatar를 사용한다.

## 이미지 한도

- PNG, JPEG, WebP, GIF만 허용하며 SVG는 허용하지 않는다.
- 최대 2MiB(2,097,152바이트), 가로·세로 각각 최대 2048픽셀이다.
- 움직이는 이미지는 최대 100프레임, 캔버스 픽셀 수 × 프레임 수가 16,000,000 이하여야 한다.
- 선언 MIME과 magic bytes가 일치해야 하며 컨테이너 구조·길이·해상도를 검사한다.
- PNG는 청크 CRC와 압축 해제 크기·스캔라인 필터도 검사한다. 압축 해제 상한은 헤더에서 계산한다.
- JPEG/GIF/WebP는 컨테이너와 프레임 헤더를 검사하며 전체 픽셀 디코딩·재인코딩을 수행하지 않는다.
- 파일명·이미지 본문·스토리지 예외 원문을 로그나 응답에 남기지 않는다.

포맷 기준: [PNG 명세](https://www.w3.org/TR/png-3/),
[WebP 컨테이너 명세](https://developers.google.com/speed/webp/docs/riff_container).

## 비공개 저장과 실패 처리

기존 앱 키의 GetObject/PutObject 권한으로 사용할 수 있도록 비공개 버킷의
`gadoc/docs/profile-avatar/<userId>/<무작위 버전>.<확장자>` 전용 namespace를 사용한다.
이 namespace는 기존 `/api/files` 경로 문법과 일치하지 않아 일반 첨부 경로로 읽을 수 없다.
버킷·정책·자격 증명·인프라를 변경하지 않으며 공개 URL이나 서명 토큰을 발급하지 않는다.
프로필 이미지 응답에는 `private, no-store`, `nosniff`, sandbox CSP를 적용한다.

교체는 이미지 업로드 후 `avatarUrl`의 이전 값을 조건으로 원자적 비교·교환한다. 동시에 다른 요청이
변경했다면 409로 거절한다. 서버 저장 실패 시 기존 참조를 바꾸지 않으며 클라이언트도 성공 응답 전에
미리보기를 현재 프로필로 확정하지 않는다. 업로드·삭제 실패 시 선택한 파일과 미리보기를 유지하여
재시도할 수 있다. 브라우저 임시 URL은 선택 취소·교체·화면 종료 때 해제한다.

삭제와 교체 후에는 먼저 현재 참조를 확정해 이전 URL을 폐기하고, 해당 관리 객체의 내용을 빈 데이터로
덮어쓴다. 기존 키에 없는 DeleteObject 권한을 요구하지 않는다. 객체 정리가 실패해도 이전 URL의 접근은
복원하지 않는다. 정리 경고에는 객체 경로·파일명·예외 원문을 넣지 않는다. 실패한 정리와 DB 타임아웃으로
남을 수 있는 비참조 객체의 별도 정리 작업은 이 기능에 포함하지 않는다. DB 타임아웃은 실제 확정 여부가
불명확할 수 있으므로 현재 이미지일 가능성이 있는 새 객체를 임의로 지우지 않는다.

Socket.IO `/profile`은 인증된 계정별 방에 연결한다. 변경 시 본인과 현재 공유 워크스페이스 멤버에게
사용자 ID만 무효화 신호로 전달한다. 클라이언트는 ACL을 다시 검사하는 API로 최신 identity를 가져온다.
포커스·온라인 복귀·소켓 재연결 때도 갱신한다. `profileUpdatedAt`이 오래된 응답으로 최신 변경·삭제를
덮어쓰지 않는다. 이미지 로드 실패 시 공통 Avatar는 이니셜로 표시한다.

## 격리 검증

운영 업로드·DB 쓰기·계정 생성·Electron/실기기 실행은 이 검증에 포함하지 않는다.
로컬 프로필 검증은 기존 18094/3202를 건드리지 않고 아래 전용 자원을 사용한다.

| 자원 | 값 |
| --- | --- |
| MongoDB | `127.0.0.1:27127/gadoc_profile_verify` |
| MinIO | `127.0.0.1:19000`, 새 비공개 버킷 `gadoc-profile-verify` |
| API / 웹 | `127.0.0.1:18095` / `127.0.0.1:3203` |

시작 전에 포트 사용 여부와 DB·버킷의 소유권을 확인한다. 기존 저장소·공유 env를 초기화하지 않는다.
스토리지에는 프로필 검증용 합성 이미지와 메타데이터만 쓰고, 본인이 만든 데이터·객체만 정리한다.
SSD 여유가 15GiB 미만이면 설치·빌드를 중단한다.

서버·웹 유닛과 빌드는 저장소 표준 명령을 사용한다. Node 22+, pnpm 10.34.9와 기존 의존성만 필요하다.
전용 API·브라우저 시나리오는 해당 자원에 연결한 서버·웹을 실행한 상태에서 다음과 같이 실행한다.

```bash
SLACORD_PROFILE_VERIFY=1 \
SLACORD_E2E_BASE_URL=http://127.0.0.1:3203 \
SLACORD_E2E_API_URL=http://127.0.0.1:18095/api \
SLACORD_E2E_SOCKET_URL=http://127.0.0.1:18095 \
pnpm exec playwright test tests/e2e/profile-avatar.e2e.spec.ts
```

이 테스트는 명시적으로 선택한 로컬 격리 스택과 기존 GitHub Actions의 임시 `slacord_ci`/`slacord-ci`
스택에서만 실행된다. 공유 환경에서 실수로 데이터를 만들지 않도록 다른 환경에서는 건너뛴다.
테스트 이미지는 메모리에서 합성하며 이미지 파일·토큰·브라우저 trace를 Git에 보관하지 않는다.

검증 항목은 네 포맷의 실제 업로드·읽기, MIME 위장·SVG·용량·해상도·프레임 한도, 본인/타인 쓰기,
공유 멤버/외부 계정/미인증 이미지 ACL, 일반 첨부 경로 우회와 MinIO 익명 접근 차단이다.
1440×960 및 390×844 브라우저에서는 키보드 파일 선택, 저장·삭제 실패와 재시도·초안 보존,
다른 탭·다른 사용자의 기존 채팅 메시지 반영, 새로고침, 이메일 표시 범위와 가로 넘침을 검사한다.
저장소·DB 실패와 동시 변경은 서버 유닛에서, HTTP 503·연결 실패는 브라우저 요청 주입으로 검사한다.

- 서버·웹 타입 검사와 production 빌드, 프로젝트 메타데이터 5개 검사, 추가 파일의 포맷 검사가 통과했다.
- 격리 API와 Chromium 브라우저 수용·회귀 25개가 통과했다. 전용 API 1개와 desktop/mobile viewport
  2개 외에 설정·반응 참여자·스레드·비공개 첨부·문서 자동 저장/실패 복구·분할/드래그를 실행했다.
- 실제 테스트 DB에서 해당 fixture의 멤버십을 회수한 직후 기존 이미지 URL 접근이 차단되었고,
  삭제 후 MinIO HeadObject로 이전 객체의 ContentLength가 0임을 확인했다.
- 1440×960 및 390×844의 합성 프로필 편집 화면을 실제 렌더링해 확인했다. 사용자 이미지·토큰·캡처는 Git에 넣지 않았다.
- SSD 하한 미달 때 설치·빌드를 중단했고 17GiB 이상 회복한 뒤 감시하며 재개했다. 운영·공유 env·기존 DB/버킷과
  다른 작업의 18094/3202는 변경하지 않았다. 실제 Electron·실기기·운영 업로드/계정 생성은 실행하지 않았다.
