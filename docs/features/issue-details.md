# 이슈 상세와 Markdown

## 동작

이슈 보드, 알림, 연결된 자료, 직접 URL에서 기존 이슈를 열면 읽기 화면이 먼저 표시됩니다. 본문과 상태·우선순위·담당자·라벨·수정 시각을 분리하며, 넓은 모달과 좁은 옆 패널은 각 화면의 실제 폭에 맞춰 배치합니다.

편집 권한이 있는 멤버는 `편집`을 눌러 원문을 수정합니다. 설명 입력칸은 크기 조절이 가능하며 Markdown 미리 보기로 전환해도 초안을 유지합니다. 저장 후 상세로 돌아오고, 취소는 확인 후 서버에 저장된 값으로 돌아옵니다. 생성은 기존과 같이 입력 화면에서 시작합니다.

## 지원 범위

- 제목, 문단, 강조, 목록, 체크리스트, 인용, 코드 블록, 표, 링크를 렌더링합니다.
- 원문은 기존 issue.description에 그대로 저장합니다. 기존 데이터 변환이나 별도 복제는 없습니다.
- raw HTML, 실행 가능한 URL, 프로토콜 상대 URL을 허용하지 않습니다. Markdown 이미지는 자동 요청 대신 직접 여는 링크로 표시합니다.
- Mermaid 실행, 본문 첨부 업로더, 임의 HTML 편집은 이 변경에 포함되지 않습니다.

렌더러는 [react-markdown](https://github.com/remarkjs/react-markdown)과 [remark-gfm](https://github.com/remarkjs/remark-gfm)을 사용합니다. raw HTML 처리 플러그인을 활성화하지 않습니다.

## 연결 자료

기존 IssueLinksService의 권한 검사를 통과한 자료만 표시합니다. 문서는 열람 가능한 상위 문서 경로를 함께 표시하고, 숨겨진 상위 문서의 이름이나 ID는 반환하지 않습니다. 경로 탐색은 순환과 과도한 깊이를 제한합니다.

메시지는 채널과 채널 메시지/스레드 답글 구분 및 작성 시각을 제공합니다. 답글 링크는 채널 페이지가 부모 메시지를 조회한 뒤 정확한 스레드를 열도록 하며, 일반 메시지는 기존 시각 기반 이력 탐색을 유지합니다. 원문으로 이동하거나 기존 `옆에 열기`를 사용할 수 있습니다.

연결·해제는 즉시 저장되며 본문 편집 저장과 별개입니다. 자료 연결은 원문을 복사하거나 업무 소유 프로젝트를 바꾸지 않습니다.

## 검증과 배포

`tests/e2e/issue-details.e2e.spec.ts`는 읽기/편집/미리 보기, 실패 후 재시도, 원문 유지, 동시 수정 충돌, 모바일·guest 권한, 외부 이미지 자동 요청 차단, 오래된 답글과 하위 문서의 실제 이동을 검사합니다. 기존 연결·드래그·알림·DB 이슈 검사는 읽기 우선 동작을 기준으로 유지합니다.

코드 병합, CI 통과와 운영 배포는 별도 단계입니다. 배포 완료는 공개 `slacord-release.json`의 정확한 main SHA와 운영 상태를 확인한 뒤 기록합니다. 인프라 이관 중에는 운영 DB의 상태·문서 갱신과 자동배포 승격을 조율해 진행합니다.
