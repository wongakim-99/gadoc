# Slacord 디자인 검토 자료

**현재 상태: 채택하지 않음. 아래 시안은 실제 제품 개선의 기준이 아니다.**

2026-10-26 사용자 피드백: 색상·디자인 시스템 개선을 서비스 구조 재설계로 확대하여 기존 Slacord와 노션형 문서의 장점을 보존하지 못했다. 이 시안과 정보 구조 변경안은 철회하고 조사 이력으로만 보관한다. 실제 제품 코드는 변경하지 않았다.

후속 기준은 기존 dev의 채널/DM/허들/이슈/공지 및 문서 트리/블록 편집/자동 저장이다. 실제 화면 위에서 색상·타이포·간격·테두리·상태·컴포넌트 일관성을 개선한다. 데이터베이스는 기존 문서 기능 안에서 확장하며 프로젝트 중심 앱이나 별도 회의 앱으로 대체하지 않는다. 아래 문서의 구현 순서는 후속 작업 지시가 아니다.

- [통합 UX 설계 v2](integrated-workspace-ux.md): 회의·대화·페이지·데이터베이스의 정체성, 관계, 생성/저장/공유, 자료 관리, 권한과 실패 상태, 구현 경계 및 완료 판정.
- [상호작용 프로토타입 v2](flow.html): 동일 기록을 회의록·업무 DB·프로젝트·내 작업에서 재사용하는 흐름 검토. flow.html/css/js를 같은 폴더에서 정적 제공하거나 로컬 파일로 연다.
- [초기 색상 시안 v1](preview.html), [초기 조사](workspace-direction.md): 탐색 기록이며 승인된 디자인이 아니다.

## 프로토타입에서 직접 확인할 것

1. 프로젝트에서 `회의 준비`를 연다. `회의 시작 → 통화 종료`를 눌러 준비/진행/정리 상태를 확인한다. 실제 통화는 시작되지 않는다.
2. `논의를 작업으로 만들기`에서 담당자·기한·프로젝트 관계를 확인하고 생성한다. 작업 상세에 원래 회의가 연결된다.
3. 업무 데이터베이스에서 같은 항목을 찾는다. 프로젝트/담당자 필터, 표/보드 전환을 해본다.
4. 작업을 완료로 바꾼다. 프로젝트 완료 집계, 내 작업, 회의록의 후속 작업에 같은 상태가 표시되는지 확인한다.
5. 작업 본문을 수정한 뒤 다른 보기에서 연다. 동일 ID/본문이 유지된다. 입력은 시안 메모리에 즉시 반영된다.
6. 프로젝트의 `이 보기 제거`를 눌러도 업무 원본의 항목은 남아 있다. `업무 보기 다시 연결`로 같은 항목을 다시 표시한다.
7. 대화의 `자료로 남기기`로 원문에 연결된 자료를 만들고 자료실에서 확인한다.

## 검증한 범위

Playwright로 회의 준비/진행/종료/확정, 같은 작업의 4개 보기, 관계 탐색, 동일 본문 수정, 작업 완료 집계, 보기 제거 시 원본 보존, 필터/보드 전환, 회의 내 동일 제목 작업의 중복 방지, 모바일 가로 넘침/탐색, reduced-motion 및 페이지 오류 부재를 확인했다. 모달 배경은 inert 처리하며 키보드 포커스를 가둔다. 데스크톱/모바일 화면을 시각 확인했다.

## 검증하지 않았거나 구현하지 않은 것

- 프로토타입의 저장은 브라우저 메모리뿐이다. 새로고침 후 유지, 서버/API, 실제 회의/녹음, 권한·검색·멀티유저는 구현하지 않았다.
- 표/보드와 고정된 프로젝트 관계·완료 집계만 구현했다. 범용 속성 생성/수식/롤업 엔진/캘린더/폼/자동화/스키마 변경 UI가 아니다.
- 새 DB 생성·일반 문서의 DB 편입·스키마 매핑·관계 역참조·공유 설정·삭제/복원은 v2 문서의 설계 범위이며 아직 실행 가능한 화면이 아니다.
- 확정 후 수정 표시, 공유 알림, 개인/공유 보기 저장과 URL/뒤로가기 복원은 아직 시안에 없다.
- 중복 방지는 시안의 회의 ID+제목 비교이며 실제 서비스의 원문 ID 기반 멱등성 계약을 대체하지 않는다.
- 실제 사용자 이해도 시험, 보조기술 검사, 최종 타이포/아이콘/밀도/전체 테마 검토는 남아 있다.

이 프로토타입을 제품 기능 또는 비주얼 디자인의 완성본으로 취급하지 않는다. 실제품 구현 전에 객체와 상호작용을 검토하는 도구다.
