# 연결 작업 공간: 로컬 검토본

기존 Slacord의 채널·DM·허들·문서 트리·자동 저장 흐름을 유지하면서 문서, 대화, 이슈, 공지를 나란히 보고 참조를 전달하는 기능을 적용했다. 브랜치는 `feature/connected-workspace`이며 원격 push 및 PR 변경은 사용자 허용 전까지 진행하지 않는다.

## 사용 흐름

1. 실제 서비스 http://127.0.0.1:3002 에서 워크스페이스를 연다.
2. 상단 **나란히 보기**에서 문서·대화·이슈·공지 중 옆에 열 내용을 고른다.
3. 구분선을 드래그하거나 키보드 좌우 방향키로 너비를 조절한다. Home 키는 50:50으로 돌아간다. 좌우 교환은 내용을 다시 로딩하지 않는다.
4. 문서 상단, 메시지 동작 메뉴, 이슈 상세, 공지 카드의 **참조 준비** 버튼을 누른다.
5. 대상 편집기에서 **참조 넣기**를 누른다. 문서는 기존 자동 저장을 사용하고, 메시지 전송·이슈 저장·공지 게시는 직접 확정한다.
6. 저장된 링크를 누르면 관련 내용을 옆 영역에 연다. 메시지는 원문 ID와 시간을, 이슈·공지는 각각의 항목 ID를 유지한다.

모바일에서는 두 영역을 탭처럼 전환하며 편집기를 유지한다. 사이드바는 기본 작업의 탐색을 맡고, 옆 영역은 기본 작업에서 메뉴를 이동해도 유지된다. 여러 탭을 무제한으로 여는 탭 관리자는 이번 범위에 포함하지 않는다.

## 데이터와 보호 동작

- 참조는 실제 문서 본문의 링크 또는 채팅·이슈 설명·공지 본문의 Markdown 링크로 저장된다. 링크 표시명은 삽입 당시 값이며 자동으로 최신 제목을 반영하지 않는다.
- 메시지 원문이나 비공개 자료 본문을 자동 복사하지 않는다. 연결을 열 때 기존 API 권한을 그대로 적용한다. 사용자가 선택한 자료의 제목은 참조 표시명으로 전달된다.
- 문서 저장 실패 시 분할 닫기/교체를 중단하고 초안을 유지한다. 미전송 메시지·미저장 이슈·미게시 공지는 닫기/교체 전에 확인한다.
- 같은 문서를 두 영역에서 중복 편집하지 않도록 일반 열기와 주 영역의 중복 경로를 보호한다. 별도 브라우저 창의 동시 편집 충돌 해결은 기존 제품의 미구현 범위다.
- 문서 제목 변경, 이슈 변경, 공지 변경을 같은 작업 공간의 다른 영역에 전달한다. 메시지는 기존 Socket.IO를 사용한다.
- 분할 상태와 참조 선택은 현재 작업 세션의 UI 상태다. 새로고침 후 분할 조합/초안 복원은 지원하지 않으며, 저장 완료된 참조 링크는 서버에 유지된다.

## 구현 결정

기존 채팅과 이슈는 전역 상태 저장소를 사용한다. 현재 화면 컴포넌트를 동일 React 트리에 두 번 마운트하면 서로의 상태를 덮어쓸 수 있으므로, 보조 영역은 **동일 출처의 기존 라우트를 별도 browsing context에서 실행**한다. 보조 화면에서는 자체 사이드바와 분할 도구를 생략한다. 기존 편집기와 API를 재사용하며 메인 문서 상태를 유지한다.

연결 프로토콜은 origin, workspace ID, 실제 frame/parent source를 검사한다. 라우트는 해당 워크스페이스의 문서·채널·이슈·공지만 허용한다. 닫기 요청은 보조 영역의 저장/초안 보호 응답을 기다리며, 응답이 없으면 닫지 않는다. 추가 라이브러리와 서버 스키마 변경은 없다.

이 선택은 로컬 검토 가능한 첫 적용을 위한 것이다. 패널별 상태 저장소와 라우팅을 분리한 네이티브 패널 렌더러로 전환하는 것이 장기 방향이다. 현재 방식은 보조 앱 런타임·Socket 연결 비용이 있으며, 분할 상태의 뒤로 가기/새로고침 복원과 데스크톱 패키지 통합은 별도 검증이 필요하다. 두 영역 동시 허들 참여는 검증하지 않았다.

## 후속 범위

- 서버의 권한 검증을 포함한 명시적 리소스 관계와 역링크 목록
- 프로젝트·서비스 범위별 연결 자료와 진행 상태 모아보기
- 문단 단위 참조, 문서 내 사람 멘션, 연결된 스레드 시작
- 회의록 DB의 날짜·참석자·결정·후속 이슈 속성과 표/보드/캘린더
- 공지 대상·확인 상태 및 승인 흐름
- 다중 탭, 세션 복원, 패널별 네이티브 상태 격리

이 항목들을 구현한 것처럼 취급하지 않는다. 이번 검토 대상은 기존 제품에서 분할과 참조 전달이 자연스럽게 이어지는지다.

## 검증 결과와 캡처

- Web TypeScript 검사 통과.
- 단위 테스트 77개(22개 파일) 통과.
- 기존 문서/워크스페이스 브라우저 10개 + 실제 API 연결 시나리오 5개 통과.
- 문서↔채팅 참조 저장·재접속·원문 열기, 이슈 참조 저장 실패/재시도, 이슈→공지 게시, 모바일 전환, 두 채널 상태 격리, 보조 초안 유지, 문서 저장 실패 시 닫기 중단 및 재시도, 보조 문서 제목의 사이드바 반영 검증.
- 실제 운영 배포, 원격 CI, 데스크톱 패키지 검증은 수행하지 않았다.
